# Procedural2 original starter art

Copyright 2026 Pelican Mapping. MIT License, as in the repository LICENSE.txt file.
All geometry and textures in this directory are original, generated by
`tools/procedural2/generate_starter_assets.py`. No third-party art is incorporated.

This is an editable starter set, with a stylized appearance, rather than final production art:
broadleaf tree, conifer, leafy shrub, grass tuft, fern, boulder, and a synthetic canopy cluster.
Models are Z-up, in meters, rooted at the ground. Near models have opaque colored geometry;
coarse models have two crossed vertical cards plus a horizontal crown card, six triangles total.
The three albedo views are baked from the same near geometry, with transparent coverage and
RGB dilation around cutouts. Lighting and shadows come from the runtime, not a baked sun direction.
The fourth atlas tile is unused padding to keep dimensions powers of two.

Impostor normals describe the crown volume, not the orientation of the supporting card. The coarse files
mark them with `Chonk::NORMAL_TECHNIQUE_VOLUME` (3): `VertexAttribArray 6 UByteArray`, bound overall.
The embedded tree cards in the static cluster carry the same marker. This preserves their upward component
when viewed from behind, while ordinary near leaves still reverse geometric normals on their back faces.
It also preserves each card's atlas coordinates on either side. No additional texture, vertex, or instance data
is allocated for this distinction; it uses Chonk's existing normal-technique byte. Custom low-poly coarse meshes
keep the default technique unless their authored normals deliberately represent a volume.

The canopy prototype contains 13 fixed trees. Its near representation assembles their individual
impostors (78 triangles); its coarse representation is a single aggregate (six triangles).
It is a separate population experiment, **not** an automatic replacement for nearby individual trees.
The roots share a local plane: this prototype is suitable for gently sloped ground only.
Matching forest outlines, terrain variation within a cluster, exclusions and holes belongs to Step 4.

Regenerate with Python 3.10+, numpy, and Pillow with BCn encoding support (validated with Pillow 12.3):

```text
python tools/procedural2/generate_starter_assets.py
```

`manifest.json` records dimensions and triangle counts. Models reference BC3/DXT5 DDS atlases with complete
mip chains down to 1x1. PNGs remain editable source images. Compression and mip generation happen offline;
TextureArena uploads the compressed blocks without asking the driver to compress or generate mips.
The regular osgDB DDS plugin reads these files; no runtime Python or Basis transcoder is required.
The DDS payload is bottom-up to match OSG's default DDS reader and the original PNG texture orientation.
Box-filtered mips retain dilated RGB independently of alpha and keep the existing shader's mip compensation.

To compress the existing PNGs and update generated model references without rebaking geometry:

```text
python tools/procedural2/generate_starter_assets.py --compress-only
```

The full baker and `--canopy-only` also emit DDS automatically. Custom asset catalogs still control their own
texture formats. This reduces preparation work on asset uploads; it does not change the residency policy below
or guarantee that all sources of frame stalls are eliminated.

Run from `tests` after `osgearth_shell.bat`:

```text
osgearth_imgui procedural2-art.earth --sky2 --shadows --nvgl --samples 4 --vegetation2
osgearth_imgui procedural2-canopy.earth --sky2 --shadows --nvgl --samples 4 --vegetation2
```

The Vegetation2 demo earth files now select the textured PBR catalog in `../pbr`.
This original starter set remains available by switching the catalog paths back to this directory;
`procedural2-grass.earth` retains the separate optional GPU grass experiment with PBR asset fallback.

The catalog accepts static groups, affine matrix transforms and geometry with standard textures.
Animated models, callbacks, custom programs, nested LOD and paging nodes are rejected. Each entry
declares `near` and `coarse` files. A population's `models/model` list selects equally among entries
using a separate deterministic hash of its placement ID. An empty list uses the built-in placeholder.
Procedural grass ignores this list; turning the experiment off restores the selected asset grass.

The layer's `asset_budget_mb` limits **admitted canonical mesh/material/image content**, with a
conservative mip allowance. This is not an overall GPU memory limit: instance/visibility buffers,
temporary decoder allocations, driver copies, and deferred GL deletion are outside this accounting.
Near and coarse files load together on first use, except that `lod_pixels=0` loads only the near file.
They share one Chonk bundle until the final drawable releases it. TextureArena then releases orphaned
textures on update. No invisible warm cache keeps a population's art resident after it pages out.

On failed admission, the layer requests its existing built-in placeholder at the same positions.
Fallbacks count against the same budget. If even a fallback cannot fit, the page cannot publish.
Failed loads are retried by subsequent page requests after five seconds, avoiding a retry storm;
already published fallback pages refresh when repaged or when the population is reapplied.
The ImGui residency section exposes failures and budget denials. A practical budget must fit the
working set; this checkpoint does not evict assets still in use or automatically lower visual quality.

Current limits: three-view impostors can reveal crossed planes at oblique angles, and their normals
approximate the crown instead of using baked normal/depth maps. Leaf transmission, production wind,
asset-specific materials, alpha-coverage-preserving mipmaps, and distant terrain color integration remain later work.


September 27: `tests/procedural2-canopy-osm.earth` now exercises the separate Step 4B hierarchy. It compiles real
coverage into terrain-fitted instances of shared procedural crown templates, with two aggregate page levels before
detailed tree pages. It does not use the static 13-tree catalog clump above. Original near/impostor tree assets remain
in use for detailed pages and explicitly mapped trees. See `docs/design/procedural2-plan.md` for current limits and controls.

The 4B procedural templates now use four irregular arrangements of nine crowns rather than a repeated 3x3 layout.
Eight occupancy levels reuse those arrangements, retaining 108 triangles per patch. Patch widths and offsets also
vary deterministically within each page partition; shared art stays inside its exclusion-certified footprint.

The runtime canopy templates also carry a crown index for nine separable pieces. Each page stores a compact mask
of fully permitted crowns at mixed boundaries; it reuses the same meshes and does not create new boundary assets.
Complementary screen-door coverage overlaps pages during refinement. Tree/aggregate color and projected coverage
matching remain part of Step 4B's appearance work.

The procedural aggregate templates now use smooth, upward-biased volume normals. Their lighting frame follows
geographic up and the patch rotation, without the footprint stretch or terrain-fit shear that moves the proxy
vertices. Both canopy tiers therefore keep the same foliage response as patch size changes. The silhouette,
triangle count, crown mask and base palette are unchanged; shadows still use the terrain-fitted geometry.


Source-derived canopy pieces (`broadleaf-canopy.osg`, `conifer-canopy.osg`) each bake five of their original source trees
into a three-view albedo/alpha atlas and six-triangle proxy. Rebuild only these pieces with:

```text
python tools/procedural2/generate_starter_assets.py --canopy-only
```

An asset can supply the reusable piece alongside its individual representations:

```xml
<asset name="broadleaf" near="broadleaf-near.osg" coarse="broadleaf-coarse.osg" canopy="broadleaf-canopy.osg"/>
```

A population's `models` list now supplies both individual and aggregate art. Without `canopy`, aggregation uses `coarse`;
without a model list, it retains the procedural placeholder templates. Canopy sources must be static, rooted, Z-up
representations with positive height and at most 128 triangles. A broken explicit reference reports an error.
Prepared canopy proxies with authored volume normals retain them; ordinary carrier-card normals get a crown-volume
approximation. Nine pieces reuse source textures/materials inside the existing exclusion footprints, giving 54 triangles
per starter template. The terrain-fit transform and nine-bit piece mask remain per-instance metadata.

`canopy-manifest.json` records the baked pieces. They contain source albedo and transparency, not baked sunlight.
The baker currently accepts our procedural meshes; arbitrary prepared model files work at runtime, while a general
model-file baking tool is future work. Aggregate alpha minification uses Chonk's mip compensation; exact coverage and
shadow matching across representations remains part of 4B.
